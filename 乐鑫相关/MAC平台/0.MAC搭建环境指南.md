# MAC搭建环境指南

EIM的安装引导链接：https://docs.espressif.com/projects/idf-im-ui/en/latest/

## 问题回顾

在 M4 Mac mini 上安装乐鑫 ESP-IDF 开发环境时，EIM（ESP-IDF Installation Manager）无法识别已安装的 Python 3.12，持续报 "Python 3.9.6 is not supported"。

### 踩坑路径

| 尝试                                | 结果               | 原因                                                         |
| :---------------------------------- | :----------------- | :----------------------------------------------------------- |
| 官网下载 `.dmg` 安装 GUI 版 EIM     | ❌ 检测失败         | `.app` 不读取 `.zshrc`，PATH 里没有 pyenv                    |
| `pyenv` 安装 Python 3.12.3          | 终端正常，EIM 不认 | 同上，GUI 应用不走 shell 初始化                              |
| `brew install python@3.12` 独立安装 | 终端正常，EIM 不认 | GUI 版 EIM 的 PATH 是系统默认的，没把 `/opt/homebrew/bin` 放前面 |
| `brew install --cask eim-gui`       | ❌ 同样检测失败     | 本质还是 `.app`，问题一样                                    |
| `brew install eim`（CLI 版）        | ✅ 成功             | 命令行工具继承终端环境，正确读取 pyenv/Homebrew 的 Python    |

### 关键教训

1. **macOS 的 `.app` 与终端是两个世界**：图形应用不读取 `.zshrc`、`.bash_profile` 等 shell 配置，pyenv 的 PATH 注入对它们无效
2. **PATH 优先级只在终端生效**：即使把 `/opt/homebrew/bin` 放最前面，GUI 应用启动时看到的仍是系统默认 PATH
3. **CLI 工具才是正确选择**：命令行版本 `eim` 继承当前 shell 环境，能正确识别 pyenv 或 Homebrew 管理的 Python
4. **不需要重复安装 Python**：pyenv 的 3.12.3 和 Homebrew 的 3.12 都可以，CLI 版 EIM 都能检测到

### 最终方案

```bash
# 1. 确保 pyenv 或 Homebrew Python 已安装（二选一即可）
pyenv install 3.12.3 && pyenv global 3.12.3
# 或
brew install python@3.12

# 2. 安装 CLI 版 EIM
brew tap espressif/eim
brew install eim

# 3. 直接使用
eim wizard   # 交互式安装 ESP-IDF
```

GUI 版 EIM 对 macOS 用户来说是个陷阱，CLI 版才是正确打开方式。

## 配置EIM

### 第一步：启动安装向导

```bash
eim wizard
```

这会进入交互式界面，引导你选择：

- **语言**：选 `cn`（中文）或 `en`
- **ESP-IDF 版本**：推荐 `5.2`（稳定版）或 `5.3`（较新）
- **目标芯片**：根据你的开发板选择
  - `esp32`（经典款）
  - `esp32s3`（AI 加速，推荐）
  - `esp32c3`（RISC-V，低成本）
- **安装路径**：默认 `~/esp` 即可
- 选择特性

| 选项              | 作用                                                        | 是否需要                                               |
| ----------------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| **core**          | ESP-IDF 核心工具链：交叉编译器、CMake、Ninja、Python 依赖等 | ✅ **必选**，没有它什么都做不了                         |
| **test-specific** | 运行 ESP-IDF 特定测试脚本的包（pytest 等测试工具）          | ❌ 只有要给 ESP-IDF 框架本身跑测试才需要                |
| **ci**            | ESP-IDF 持续集成（CI）脚本依赖的包                          | ❌ 乐鑫内部/框架开发者用，普通用户不需要                |
| **docs**          | 本地构建 ESP-IDF 文档的包（Sphinx 等）                      | ❌ 除非你不想看在线文档、要自己编译文档                 |
| **ide**           | IDE 支持组件（配合 VS Code / Eclipse 的 ESP-IDF 插件）      | ⭕ 打算用 **VS Code + ESP-IDF 插件** 就勾选             |
| **mcp**           | MCP（Model Context Protocol）服务器功能                     | ⭕ 想让 AI 助手直接操作 ESP-IDF（构建、烧录、监控）再选 |

| 选项             | 作用                                                 | 是否需要                                                 |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| **cmake**        | CMake 构建系统，ESP-IDF 编译项目要用它               | ⭕ 见下方说明                                             |
| **qemu-xtensa**  | Xtensa 架构芯片的模拟器（ESP32、ESP32-S2、ESP32-S3） | ❌ 只有想在电脑上**模拟运行固件**、没有实体开发板时才需要 |
| **qemu-riscv32** | RISC-V 架构芯片的模拟器（ESP32-C3/C6/H2 等）         | ❌ 同上                                                   |

### 第二步：安装完成后激活环境

```bash
# 查看已安装版本
eim list

# 激活指定版本（替换为你实际安装的版本号）
eim select 5.2

SP-IDF 不会把 idf.py 安装到系统全局路径里。每个版本的环境变量（PATH、工具链路径等）都需要在当前终端里手动"激活"一次。eim select 只是选中了版本，它没法修改你当前终端的环境——所以提示信息里明确写了

在当前终端执行：（单次）
source /Users/felix/.espressif/tools/activate_idf_v6.0.2.sh

# 验证
idf.py --version
```

`idf.py` 不是装在系统全局路径里的命令，它在 ESP-IDF 的安装目录内，而且运行它还依赖一整套环境：

- `IDF_PATH` 等环境变量
- ESP-IDF 专用的 Python 虚拟环境
- 编译工具链（cmake、ninja、xtensa-esp32 交叉编译器等）的 PATH

这些全都由那个 `activate_idf_v6.0.2.sh` 脚本一次性配好。不执行它，终端根本不知道 `idf.py` 在哪，也没有配套的依赖，所以直接敲 `idf.py --version` 只会报 `command not found`。

### 第三步：配置 shell 自动激活（永久）

- 把下面加到 `~/.zshrc`，这样新终端自动加载 ESP-IDF：（添加一个别名到环境变量中）

```bash
# ESP-IDF 环境（根据实际安装路径调整）
echo "alias get_idf='source \$HOME/.espressif/tools/activate_idf_v6.0.2.sh'" >> ~/.zshrc
source ~/.zshrc
```

**每开一个新终端窗口**，顺序是：

```
get_idf              # 激活环境（就是之前配置的别名）
idf.py --version     # 现在就能用了
idf.py build         # 后续命令随便用
```

**别名存在哪？**

`~/.zshrc` 是 zsh 的配置文件，**每次打开新终端，zsh 启动时都会自动读一遍**。你在里面写了 `alias get_idf='...'`，所以每个新窗口启动后，`get_idf` 这个短命令就被"登记"好了——这才是"任何时候都能找到"的原因，和环境变量没关系。

**环境变量什么时候才有？**

只有当你真正敲下 `get_idf`、脚本跑起来的那一刻，`PATH`、`IDF_PATH` 这些环境变量才会被设置，而且**只存在于当前这个终端会话里**，关窗即失效。

**整个链条是这样**

```plain
打开终端
   ↓
zsh 自动读 ~/.zshrc → get_idf 别名登记完毕（此时环境还没激活）
   ↓
你敲 get_idf → 脚本执行 → PATH 等环境变量注入当前终端
   ↓
idf.py 可用了
```

#### 两个机制对比

|        | 别名（alias）                | 环境变量                         |
| :----- | :--------------------------- | :------------------------------- |
| 是什么 | 长命令的短名字               | 键值对（如 `PATH=/usr/bin:...`） |
| 存在哪 | `~/.zshrc`，每次启动自动登记 | 由激活脚本在运行时临时设置       |
| 有效期 | 永久（每个新终端都有）       | 仅当前终端会话                   |
| 作用   | 让你**方便地**激活环境       | 让 `idf.py` **真正能跑**         |

所以你记成一句话就是：**配置文件让别名永久可用，别名帮你一键设置环境变量，环境变量让 idf.py 能工作。**
