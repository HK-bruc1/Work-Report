# 使用VSCode搭建工作区

## 安装插件

安装IDF插件按照引导配置即可。

## 部署MCP

### 第一步：装上 mcp 功能

**前提**：EIM ≥ v0.8.1，且通过 eim 安装的是 ESP-IDF v6.0 或更新版本（v5.x 没有这个功能选项）

先看一下当前状态：

```
eim list-features
```

如果 mcp 显示 `[not installed]`，不用重装，用 `fix` 命令补上就行（fix 默认保留原有配置，加参数就是追加功能）：

```
eim fix --idf-features mcp
```

它会让你选择要修复的版本（也可以用 `-p <安装路径>` 直接指定）。装完后验证：

```
cd 你的ESP-IDF项目目录
eim run "idf.py mcp-server"
```

不再报 `MCP dependencies not available` 就说明装好了。注意：这条命令启动的是 stdio 服务，启动后会停在那里等待输入，**这是正常现象，不是卡死**——它本来就不是给人手动用的，而是给 AI 客户端调起的。

### 第二步：在 AI 客户端里启用（这才是"打开"）

MCP Server 是本地 stdio 服务，由 AI 客户端作为子进程拉起。两点提醒：

- 需要在**项目目录**（含 `CMakeLists.txt` 的那个目录）下使用，因为 MCP 是按项目工作的。
- 想先验证一下的话，可以在项目目录里跑 `eim run "idf.py mcp-server"`，如果命令停在那里没有报错，就是正常的（它在等待 AI 客户端连接），按 `Ctrl+C` 退出即可；如果报 `MCP dependencies not available` 才说明有问题。

配好之后，直接对 AI 说「帮我构建这个项目」「把目标芯片设为 esp32s3」这类话，它就会自动调用 MCP 工具了。

两层要分开看：**装是全局的，用是项目级的**。

- **安装层面是全局的**：`mcp` 功能的 Python 包装在你这个 IDF v6.0.2 的 Python 环境里，装一次，所有用这个 IDF 版本的项目都能用，不用每个项目单独装。
- **运行层面是项目级的**：每次启动的 MCP server 实例只绑定一个项目目录。因为它提供的工具——`build_project`、`set_target`、`flash_project`、看 sdkconfig 这些——本质上都是针对"某一个项目"的操作，所以它必须知道自己服务的是哪个项目（靠启动时的当前目录，或 `IDF_MCP_WORKSPACE_FOLDER` 指定）。
