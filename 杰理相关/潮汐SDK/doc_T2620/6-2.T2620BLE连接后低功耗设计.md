# T2620 BLE 连接后低功耗设计

> 更新时间：2026-10-10
> 文档状态：连接态增量设计，尚未实施本文新增的连接态共享 VDD 策略或完成对应板测；现有 RDX 传输调参机制不属于本轮新增实现
> 适用工程：T2620 / AC701N（BR28）RDX + HOGP，最多两条 Peripheral ACL
> 已实现基础：[6-0 外设低功耗与共享 VDD 管理](6-0.T2620外设低功耗与共享VDD电源管理设计.md)、[6-1 独立 PA 管理](6-1.通用功放低功耗设计.md)
> 本轮边界：只设计连接期间的增量能力，不重建未连接低功耗和 PA 管理

## 1. 目标、范围与已完成基础

### 1.1 已完成基础

| 模块 | 已有能力 | 本文处理方式 |
|---|---|---|
| 未连接低功耗 | 零 ACL 下的空闲/广播策略、共享 VDD 安全停用、断电及业务恢复 | 沿用 6-0，只做交接和防回归，不重复设计 |
| PA / PE5 | 独立跟随 DAC 模拟输出生命周期开关 | 沿用 6-1，不纳入连接态空闲计时、忙状态或关断决策 |
| 共享 VDD / PA4 | SD NAND + RGB 共用电源域，已有统一管理器、所有权和停用/恢复流程 | 复用执行机制，增加连接态资格判定和访问保护 |
| RDX 连接参数 | 传输快档、传输后延迟降档、token/generation 隔离和快档有限请求 | 第一阶段保持不变，第二阶段补齐其他链路场景 |

“已有能力”不代表所有量产验收均已完成。6-0 中保留的回归项和历史约 1.5 mA 离线数据继续由该文档维护，不能作为连接态功耗数据或本方案验收结论。

PA 的责任边界固定：DAC 模拟输出稳定后开启 PE5，关闭模拟输出前先关闭 PE5。若无声待机时 PE5 仍高，应排查音频资源释放，不由连接态管理器强制关闭。仅录音不必然需要 PA；播放是否需要 SD 则由共享外设业务事实决定，二者不能混为一项占用。

### 1.2 本次新增目标

保持 BLE 物理连接及 RDX/HID owner，从两个独立方向降低连接态空闲功耗：

1. **连接态共享 VDD**：SD NAND/RGB 的实际业务完全结束后，连续空闲 120 秒，复用安全停用流程关闭 PA4；新外设业务先恢复、后访问。
2. **BLE 参数覆盖完善**：基于现有 RDX 调参机制，后续按每条实际 ACL 的业务需求协调参数，覆盖仅 HOGP、无 owner、复合链路及双 ACL。

两条策略共享必要的业务事实，但独立计时、独立判定。BLE 慢参数不是外设断电许可；PA4 关闭也不是请求慢参数的前置条件。主机拒绝调参不能阻止安全的外设休眠。

自动关机、RDX 会话释放协议、音频生命周期和硬件电源域划分不在本轮修改范围。外设休眠不触发 `rdxclose`，不释放 owner，不主动断开 ACL。自动关机仍独立生效，测量时需记录 VM 实际配置，避免将自动关机误认为连接态休眠。

## 2. 当前代码现状与连接态缺口

### 2.1 已有 RDX 参数调整

以下为本轮核对的当前实现，不是待新增方案。主要代码在 `rdx_ble_server.c` 的 `connection_param_table`、`rdx_ble_server_transfer_param_post()` 和 `rdx_ble_server_transfer_param_run()`。

| 项目 | 当前实现 |
|---|---|
| 传输快档，索引 0 | `{6, 6, 4, 600}`：请求间隔 7.5 ms，latency 4，监督超时 6 s |
| 传输后低功耗档，索引 8 | `{60, 80, 19, 2000}`：请求间隔 75–100 ms，latency 19，监督超时 20 s |
| 快档入口 | `rdx_ble_server_request_stream_fast_param()` |
| 低功耗入口 | `rdx_ble_server_post_transfer_lowpower()` |
| 目标链路 | token 必须解析为当前有效 RDX owner，且 RDX runtime active |
| 执行上下文 | 同步发布参数意图，在 `app_core` 执行请求和定时回调 |
| 防旧事件 | token 隔离链路/会话生命周期，generation 使旧参数意图回调失效 |

间隔原始单位为 1.25 ms，监督超时原始单位为 10 ms。旧版本文的快档 `{6, 10, 4, 600}` 已由当前代码的 `{6, 6, 4, 600}` 替代。

实际链接的是 `librdxApp_patched.a`。本轮检查其 `rdx_protocol.c.o` 的 IR，确认文件列表请求、录音文件数据传输开始等路径调用快档入口；传输完成、停止清理及文件同步超时清理等路径调用传输后低功耗入口。部分入口还根据 Wi-Fi 状态选择 BLE 分支。这些是调用点证据，不代表所有命令、所有异常清理路径均已完成覆盖验收。

低功耗入口并非立即切档，其当前条件为：

1. 捕获有效且 runtime active 的 RDX token，否则不建立此次意图。
2. 从本次低功耗意图发布起等待至少 5 秒；重复发布会更新期限和 generation。
3. 到期检查 `file_send_busy`（对象存在时）、`rdx_is_file_transfer_active()` 和 `rdx_is_file_sync_busy()`。
4. 录音状态对象必须有效，`run == RECORD_STATE_STOP` 且 `process_state != REC_PROCESS_STATE_BUSY`。
5. 任一忙条件成立，再推迟 5 秒复检；token 失效则取消，旧 generation 回调直接退出。
6. 条件满足后提交索引 8 请求，并重置下一轮快档请求预算。

快档按当前实际参数 `conn_interval == 6 && conn_latency <= 4` 判断是否停止请求；未满足时，请求间隔至少 2 秒，预算最多 3 次。重复业务入口不能无限刷新同一连接的预算，提交低功耗请求或切换有效目标等路径才重置预算。

### 2.2 不能直接作为通用休眠策略的原因

- **不是连接后的通用无操作定时器**：尚未触发相关业务及低功耗入口的链路，不能据此保证自动降档。
- **不是所有 ACL 的策略**：仅 HOGP、尚无 owner、释放 RDX 后保留的 HID 链路，不具备上述有效 RDX token，不能认为已被覆盖。
- **不是完整外设忙快照**：上述降档条件未完整覆盖本地播放、DAT/索引/扫描、格式化、USB、RGB 和待执行访问。
- **请求不等于生效**：当前请求包装函数没有根据底层返回值确认提交成功；低功耗分支提交后返回，没有与快档相同的有限重试闭环。实际值以连接完成/参数更新成功事件为准。
- **错误恢复仍有边界**：当前投递失败有定时重投尝试，但定时器建立失败会记录错误，不能描述成已具备完整可靠重试机制。

因此可以复用业务通知、token 和防旧意图思路，不能在低功耗参数请求处直接附加 PA4 断电。

### 2.3 当前 PA4 为什么连接后不能关闭

`rdx_peripheral_power.c` 当前具有多层离线保护：

- `rdx_peripheral_power_vdd_busy_snapshot()` 将任一实际 ACL 计入 `BLE_LINK`。
- 空闲判定及 takeover 后复检实际连接数。
- 空闲触发、最终停用资格及业务结束复检依赖慢广播和 `rdx_adv_policy_idle_valid()`。
- 建链会恢复共享域，保障后续 ATT 业务访问；当前连接期间长期保持 PA4 高。

这些条件是离线方案的安全前提，不是可直接删除的冗余代码。连接态开放断电前，必须以独立资格及完整业务准入保护替代；只删除 `BLE_LINK`、借用广播定时器或放宽某一个复检点均不成立。

## 3. 连接态共享 VDD 策略

### 3.1 独立空闲期限

连接态采用独立配置的 120 秒完整空闲窗口，不复用 `RDX_LED_BLE_ADV_TIMEOUT_MS` 或 RDX 传输后 5 秒降档定时器。6-0 的未连接窗口也已于 2026-09-23 调整为 120 秒，旧“量产必须恢复 300 秒”不再作为本文依据；数值相同不代表共享计时状态。

| 事件/状态 | 连接态行为 |
|---|---|
| 首条 ACL 建立 | 首轮保留建链恢复；初始化、已启动的扫描及待执行业务全部结束后，才建立空闲窗口 |
| 外设业务申请 | 同步发布占用/待执行事实，使旧空闲请求失效；恢复成功后执行业务 |
| 业务运行、暂停持有文件、异步收尾 | 不计为空闲，不消耗 120 秒窗口 |
| 最后一个业务完整结束 | 从此时开始新的完整 120 秒窗口 |
| 重复空闲/结束通知 | 不重新计时，不无限延后关电 |
| 纯 BLE 保活、纯 HOGP 报告、已确认的内存查询 | 不刷新外设窗口，不要求 PA4 上电 |
| 空闲 120 秒到期 | 退出普通提示灯，复检业务，提交安全停用请求；不能直接拉低 GPIO |
| 稳定 OFF | 不保留无意义的周期轮询，等待真实业务或必要拓扑事件 |

只有“忙转空闲”或有效拓扑周期初始化可以建立新窗口。到期才发现仍忙时，取消本次空闲资格；确认业务结束后重新等待 120 秒，不能沿用已经过期的期限。缺少结束通知的预编译业务可在活动期低频复检，但未知状态不能被当成空闲。初始化完成以恢复、扫描及待执行访问实际结束为准，不能用固定建链延时或获得 owner 代替。

### 3.2 忙状态与普通灯效分离

连接态不再将 ACL 存在本身作为共享外设长期忙条件，但仍聚合：

- 录音、播放及暂停持有文件、索引写入和收尾。
- 文件传输、同步、DAT 加载、扫描、格式化和存储恢复。
- 已准入但未执行的外设命令，以及库内延后访问。
- USB MSC 准备、Host 所有权及恢复交接。
- 必要 RGB 场景，以及现有充电非 OUT、DUT、OTA 保守门禁。

必须区分“允许空闲计时”和“允许物理关断”：

- 普通连接/第二连接窗口提示灯可在计时期间显示，但不能自己永久阻止计时。
- 到期后经灯效仲裁退出普通提示；仍有必要场景或 RGB 尚未安全停用时，不允许断电。
- 剩余槽位的快慢广播事件不刷新连接态期限，也不自动重亮已超时退出的普通提示。
- 显式用户操作需要 RGB 提示时，按新的实际 RGB 业务处理；不能把所有 HOGP 按键一概视为不需要外设。
- 充电、低电、DUT、OTA 的场景逐项列明优先级；首轮不放宽当前充电/DUT/OTA 忙门禁，即使视觉灯灭也不能绕过。

普通提示退出不能覆盖业务灯或高优先级提示，不能靠无条件设置全局 OFF 实现。

### 3.3 单/双 ACL 与离线策略交接

连接数使用两个 wrapper 的实际 ACL 聚合值，不用 RDX owner、HID ready 或单个连接句柄代替。

| 拓扑变化 | 处理规则 |
|---|---|
| 0 → 1 | 同步作废旧离线停用请求，保留建链恢复；初始化完成后评估连接态窗口 |
| 1 → 2 | 作废旧连接态请求；首轮保留新建链恢复，聚合两条链路的初始化/外设业务后重新计时 |
| 2 → 1 | 作废旧请求，重新聚合并建立新窗口；不因断开本身强制上电，已 OFF 且无业务可继续 OFF |
| 1 → 0 | 取消连接态期限和请求，交还 6-0；是否恢复供电由既有离线策略决定，不携带连接态剩余时间 |
| ACL 数不变，仅 owner/能力变化 | 不将其当成外设业务；重新核对真实占用及有效 token，清理失效命令 |

双 ACL 全连接时没有广播超时，仍必须能完成连接态空闲断电。任一链路的外设业务均阻止整个共享域断电。仅 HOGP 或尚无 owner 也属于连接态，不能因无 RDX owner 漏管。

## 4. 业务准入与断电后恢复

### 4.1 开放连接态断电的前置门槛

离线方案依靠建链恢复保障随后 ATT 访问；连接内断电后，必须为每次可能访问 SD/RGB 的业务提供恢复保证。完成入口、异步访问及结束边界审查之前，不开放连接态真实断电。

以下是待实施核对表，不表示已完成接入：

| 业务类别 | 准入/恢复位置 | 占用结束边界 |
|---|---|---|
| RDX 文件列表、扫描、索引加载 | 进入预编译库或发布 worker 请求前 | 扫描、加载、结果生成涉及的最后一次外设访问结束 |
| 文件读取、传输、删除、重命名等 | 权限校验后、文件访问/排队前 | 文件关闭、队列清理及异步收尾全部结束 |
| 录音及索引保存 | 申请录音资源及延后启动前 | 停止、文件保存、索引写入全部完成 |
| 本地播放 | 打开文件及启动播放前 | 停止并释放文件；暂停仍持有资源时继续占用 |
| 格式化、存储恢复 | 明确操作准入后、首次设备访问前 | 操作和后续重建完成，所有权恢复明确 |
| RGB | 仲裁确认需要显示后、访问 SPI 前 | 场景结束，驱动不存在待完成 DMA/总线访问 |
| USB MSC | 先恢复设备侧可用状态，再交接 Host | Host 归还且设备侧协调/恢复完成 |
| 纯 HOGP 报告、纯内存查询 | 审查确认无共享域依赖后不申请电源 | 不参与共享外设占用 |

实施时按具体命令/入口补充实际接入符号、线程、异步子任务、结束通知、失败处理及对应测试。未知命令或无法证明已结束的访问保持供电；不能只检查 ATT 是否有数据，也不能让所有包无差别上电。

### 4.2 固定的访问顺序

```text
长度、权限、加密及 owner/token 校验
    -> 同步登记占用/待执行事实，作废旧空闲资格
    -> 确保共享 VDD 和目标设备恢复成功
    -> 执行或发布业务
    -> 等待最后一次异步访问及收尾完成
    -> 释放占用，重新评估是否开始完整空闲窗口
```

业务占用持续到最后一次异步访问结束。`ensure_on()` 后才登记忙状态会留下重新关电窗口；wake epoch 只能取消旧决策，不能代替持续占用。沿用固定业务事实、待启动屏障和明确完成通知，不建设通用多客户端租约框架。

申请、恢复或排队失败必须撤销本次待执行占用；如果仍有外设访问或清理未结束，则保留相应实际忙状态，不能提前报空闲。短命令即使在两个快照之间完成，也必须保留活动事实，不能让旧超时继续有效。

### 4.3 线程、协议与失败边界

- 不在关中断区执行挂载、卸载或调用会取锁的 JL BLE 查询；仅同步发布短小的活动事实/epoch，耗时转换沿用受互斥保护的执行上下文。
- 同步恢复是否可接受需测量最坏耗时及对双 ACL/HOGP 的影响，不能仅以平均恢复时间判定。
- 若改为工作任务恢复，必须一起定义 STARTING 期间的有界排队、缓冲复制、顺序、超时及失败响应；恢复未完成不得放行。
- 异步命令执行前重验链路 token。断链、RDX 释放或槽位复用后，旧命令不得借新会话执行；其已启动操作仍须正常完成资源清理。
- ATT Write Command 没有 ATT 错误响应，不能假设返回 busy 后主机会重试；按现有协议定义可用响应或排队方式。
- 恢复失败向业务返回失败，不视为可访问；不得因动态恢复失败自动格式化。非法或非 owner 请求不能通过恢复入口获得存储访问权。

## 5. 现有电源管理器的增量改造

### 5.1 保留与替换的边界

继续由 `rdx_peripheral_power.c` 唯一控制 PA4，复用 `ON_READY → STOPPING → OFF → STARTING → ON_READY`、SD0 所有权、转换互斥、三级验证模式及失败保持供电机制。

新增连接态策略状态不能与硬件电源状态混用。“空闲期限已到”只表示允许申请停用，不表示 OFF；恢复完成前也不能标记设备可访问。

| 改造面 | 设计要求 |
|---|---|
| 空闲资格 | 零 ACL 保留现有离线资格；非零 ACL 使用独立的连接态期限及业务资格 |
| `BLE_LINK` 忙位 | 只在完整连接态保护接入后调整其含义，不能先删保护再补入口 |
| 慢广播检查 | 空闲入口、takeover 后、最终断电及业务复检统一选择正确策略，不能只放宽一处 |
| generation/epoch | 请求绑定策略来源、当前拓扑/活动代次和 wake epoch；策略切换后旧请求无效 |
| 广播事件 | 连接态剩余槽位的快慢广播不得无条件唤醒 PA4、重启连接态窗口或恢复普通提示灯 |
| 业务通知 | 复用可用的业务事实和待启动保护；离线广播专属状态不能直接作为连接态许可 |
| 拓扑事件 | 区分新建链恢复与仅断开一条链路；不再用“变化后仍有连接”统一触发恢复 |
| 失败处理 | 定时器/消息投递失败保持供电或现有安全态，有限重试；未成功建立窗口不能按旧期限断电 |

### 5.2 安全停用与竞态保护

超时只向 `app_core` 提交请求，由现有管理器执行停用。必须确认文件和 worker 收尾，受控卸载 SD，停止 RGB 定时器及 SPI/DMA，设置接口安全态；各步骤具体顺序沿用已验证执行器，并保留中间失败回滚。最终复检通过后才拉低 PA4。

进入停用、takeover 后及最终断电前都必须检查当前策略资格、实际忙状态和活动代次。新业务在访问前同步发布占用并使旧请求失效；STOPPING 中到达时取消旧关断或完成受串行化保护的恢复，不能并行操作设备。关中断的最终提交区不执行会阻塞的 SDK API。

挂载/卸载、RGB 停用或所有权转换失败不允许继续盲目断电；恢复失败不允许放行业务。故障状态与正常 OFF 区分，日志保留失败步骤和所有权。不得恢复旧 PA0 电源路径，更不能将旧 `emmc_poweroff` GPIO 直接替换成 PA4。

## 6. BLE 连接参数策略

### 6.1 第一阶段保留，第二阶段完善

第一阶段保持第 2 节的既有 RDX 调参行为，不同时修改连接参数和外设断电条件，以便隔离功耗收益及回归原因。共享域关闭后仍允许既有参数请求正常运行。

第二阶段按每条实际 ACL 聚合通信需求，并将现有快/慢请求纳入同一链路决策，不能另建一条会相互覆盖的请求路径。

| 链路业务 | 后续设计方向 |
|---|---|
| 文件传输、实时数据 | 短间隔优先，现有快档作为吞吐测量起点 |
| RDX 空闲 | 现有低功耗档作为基线，补齐未经过传输也能评估空闲的路径 |
| 仅 HOGP | 评估较短间隔配合适当 latency，验证首键及释放响应 |
| 尚无 owner | 兼容服务发现及后续认领，不能因缺少 RDX token 漏管 |
| 同 ACL 的 RDX + HOGP | 同时满足传输和键盘需求，不直接套用纯 RDX 空闲档 |
| 两条独立 ACL | 分别维护意图和实际参数，不能用一个 owner 代表全部连接 |

RDX 逻辑释放后仍保留 HID 的链路也要重新评估参数，不能继续依赖已失效 RDX token。

### 6.2 请求与体验约束

参数请求绑定有效链路身份和代次，防业务抖动及无界重试；记录请求、提交结果、更新成功/失败和实际生效值。主机拒绝时继续正常业务，不强制断链、不阻止 PA4 休眠。具体参数、延迟和有限重试规则在测量后确定，不套用外设 120 秒期限。

latency 允许外设空闲时跳过部分连接事件，不表示首键一定等待整个跳过周期；JL 控制器唤醒行为及主机接受情况需要板测。参数须满足 BLE 约束，包括 `监督超时 > 2 × (1 + latency) × 最大连接间隔`，但满足约束不代表满足产品体验。

增大监督超时本身不作为省电收益；现有 20 秒档需验证异常失联后 owner 释放及重连等待。外设主动按键和主机首条下行命令分别测量。单 ACL 的电流测量还须记录剩余槽位的广播状态，避免误归因。

## 7. 分阶段实施与验收

### 7.1 实施顺序与开放门槛

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| P0：基线与入口审查 | 固定供电、仪器和调试状态；记录链路、参数、广播、PA4/PE5、电流；补全具体命令/worker 接入表 | 外设依赖、开始和结束边界可追踪；未知路径保守阻止关断 |
| P1：资格判定 | 接入连接态计时、占用屏障、灯效和拓扑交接，使用 `DRY_RUN` | 主机行为测试及实机日志证明正确申请/拒绝；PA4 保持高 |
| P2：停用与恢复 | 使用 `UNMOUNT_ONLY`，连接内停止驱动并受控卸载，再由首条业务恢复 | 首条命令、异步收尾、双 ACL、HOGP 和故障路径通过；PA4 仍高 |
| P3：真实断电 | 切换 `POWER_CUT`，验证 PA4 波形、恢复时序和反灌风险 | 存储完整性、反复睡眠/唤醒、功能与电流验收通过 |
| P4：参数完善 | 外设状态一致时比较各类 ACL 参数，再联合回归 | 功耗、首键/释放、吞吐及失联体验满足确认后的门限 |

P0–P3 不改变既有 BLE 调参策略。连接态资格未开放时保留当前“连接保持供电”的行为。三级模式复用现有执行能力，但连接态验证开关与离线策略分开控制；若实施时仍使用全局模式，则必须明确其会同时影响离线断电，测试后恢复既有产品配置，不能把离线能力降级当作正常发布行为。真实断电失败时退回 `UNMOUNT_ONLY` 定位，不通过放宽 busy 或关闭错误检查掩盖问题。
